# Dun v1.5.0

Other apps can now read and control Dun through its local API, and open Dun with
`dun://` links. This release also improves countdown customization and Android
alarm permission setup.

- **App API:** list and look up items, complete an occurrence, snooze, archive or
  restore, and start, pause, resume or reset timers. The existing reminder/timer
  creation endpoints remain compatible. Enable App connections in Settings;
  the key grants access to all items on that PC.
- **Deep links on Windows and Android:** open Dun, open a live item, or prefill a
  reminder or timer. Creation links require saving the form. Incoming links wait
  while you edit, and cancelling does not create anything.
- **Integration helpers:** a Node client, URL builder, examples, authentication
  requirements and retry guidance are in the [API guide](https://github.com/vaynealtapascine/Dun/blob/v1.5.0/docs/APP-API.md).
- **Countdowns:** choose individual units and mixed or total counts; repeating
  anniversaries can show the accumulated time since their original date.
- **Android alarm access:** keep the user-granted exact-alarm permission path
  available on Android 12 and newer. If exact alarms are unavailable, startup
  opens the app's Alarms & reminders settings after the notification permission
  result, without relying on activity pause/resume to infer an answer. Already
  granted access does not prompt; denied access retains the inexact fallback.

Downloads:

- `Dun_1.5.0_x64-setup.exe`: Windows x64 installer.
- `dun-1.5.0.apk`: signed Android ARM64 release APK, Android 7.0 or newer.
- `SHA256SUMS.txt`: checksums for both downloads.

Install over an earlier release to keep your data. Android debug builds use a
different signing key; back up before changing from a debug build.

Validation includes frontend checks and tests, Node adapter tests, Rust formatting,
Clippy and workspace tests, Windows and Android release builds, and APK signature,
version, JNI export and 16 KB alignment checks. Browser tests exercised queued
links, cancellation, saving and item navigation. Native OS link launching and the
Android permission/device matrix have not received a new device pass; see the
[device checklist](https://github.com/vaynealtapascine/Dun/blob/v1.5.0/docs/ANDROID-DEVICE-CHECKLIST.md).
